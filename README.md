# FlowCloud для OpenWrt

Служба для роутера на OpenWrt, которая направляет выбранные сайты и подсети через
туннели: Cloudflare WARP с автоматическим подбором сервера или любой VPN-интерфейс
роутера (AmneziaWG, WireGuard, OpenVPN). Всё настраивается в LuCI:
**Службы → FlowCloud**.

## Возможности

- **Несколько туннелей.** Секции можно направлять в разные туннели.
- **WARP без ручной настройки.** FlowCloud сам регистрирует устройство в Cloudflare и
  подбирает рабочую пару «сервер + профиль маскировки AmneziaWG» из пулов WARP,
  проверяя кандидатов параллельно. Рабочие пары запоминаются. Раз в 15 секунд
  туннель проверяется, и если сервер перестал пропускать трафик, подбирается новый
  без перезапуска VPN.
- **Секции, как в podkop:**
  - действие: через туннель, напрямую (исключение) или блокировать;
  - списки сообщества [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains)
    (YouTube, Telegram, Discord, Meta, Twitter и другие, у части есть ещё и подсети);
  - свои домены и свои IP-адреса и подсети;
  - ссылки на внешние списки доменов и подсетей.

  Секции проверяются сверху вниз: при совпадении срабатывает первая.
- **Статус в LuCI:** короткая сводка над вкладками (туннели с пингом, zapret2) и
  вкладка «Диагностика»: туннели с текущим сервером WARP, медианой и потерями,
  кнопка «Сменить сервер», секции, результаты проверок zapret2, DNS, проверка
  любого адреса по всем маршрутам сразу и журнал. Секции и туннели — каждый на
  своей вкладке.

## Как это устроено

```
устройство LAN ──DNS──> dnsmasq ──> flowcloudd (127.0.0.53) ──DoH──> 1.1.1.1
                                        │ домен из секции?
                                        └─> IP в набор nftables (до ответа клиенту)

устройство LAN ──пакет──> nftables (inet flowcloud): IP в наборе секции?
                              └─ марка туннеля ─> ip rule ─> таблица туннеля ─> fcwarp / Awg / …
```

- **DNS.** `flowcloudd` — DNS-прокси, в который dnsmasq пересылает запросы. Для доменов
  из секций IPv4-адреса из ответа попадают в набор секции до того, как ответ уйдёт
  клиенту, так что первое же соединение идёт правильным маршрутом. AAAA для таких
  доменов не отдаются: маршрутизация работает по IPv4.
- **Маршрутизация.** Своя таблица `inet flowcloud` метит новые соединения к адресам из
  наборов и сохраняет марку в conntrack. Уже открытые соединения не меняют маршрут.
  Для каждого туннеля есть правило `ip rule` (приоритет 103) и своя таблица (1001+).
- **Firewall.** Два include-файла fw4 (`/usr/share/nftables.d/chain-pre/forward` и
  `srcnat`) пропускают и маскируют только помеченный FlowCloud трафик. Правила fw4 и
  других служб не меняются.
- **WARP.** Трафик идёт через модуль ядра `kmod-amneziawg`, интерфейс `fcwarp`.
  Подбор сервера идёт отдельно, во временных туннелях в памяти процесса
  (amneziawg-go), а победитель применяется к интерфейсу ядра через `awg set`.
  Устройство WARP хранится в `/etc/flowcloud/warp/`.

Марки FlowCloud занимают биты `0x0f000000` и не пересекаются с podkop (`0x00100000`).

## Установка

```sh
sh <(wget -O - https://raw.githubusercontent.com/Slam00/FlowCloud-OpenWRT/main/install.sh)
```

Скрипт:
1. определит архитектуру роутера;
2. если модуля AmneziaWG нет, предложит поставить `kmod-amneziawg` и
   `amneziawg-tools` из релизов
   [awg-openwrt](https://github.com/Slava-Shchipunov/awg-openwrt) под вашу версию и
   платформу OpenWrt;
3. установит `flowcloud` и `luci-app-flowcloud`.

Вручную:

```sh
opkg install flowcloud_<версия>_<архитектура>.ipk luci-app-flowcloud_<версия>_all.ipk
```

После установки служба выключена. Настройте секции и туннели в LuCI, затем
включите FlowCloud на вкладке «Настройки».

Требования:
- OpenWrt 23.05 или 24.10 (opkg);
- от 32 МБ флеша и 128 МБ ОЗУ (служба занимает около 20 МБ памяти);
- для WARP-туннелей нужен `kmod-amneziawg`.

## zapret2: обход DPI без туннеля

Секция с действием «Через zapret2» идёт напрямую с вашего IP, на полной скорости канала,
а первые 12 пакетов каждого соединения (TCP 80/443 и QUIC) обрабатывает `nfqws2` из
[zapret2](https://github.com/bol-van/zapret2). FlowCloud сам запускает `nfqws2` и
передаёт ему трафик через свою очередь nftables, так что скрипты и списки самого zapret
не нужны.

- Устанавливается по желанию: `install.sh` спрашивает об этом (или `-z`). Ставятся
  `kmod-nft-queue`, `kmod-nfnetlink-queue` и `nfqws2` с Lua-библиотеками закреплённой
  версии zapret2 в `/usr/lib/flowcloud/zapret2`. Контрольная сумма `nfqws2` сверяется
  с `sha256sum.txt` релиза.
- **Автоподбор стратегии.** Раз в 5 минут FlowCloud открывает через zapret2 тестовые
  адреса (по умолчанию YouTube) и до трёх хостов секции, к которым устройства сети
  обращались за последние 15 минут, например видеоузлы `*.googlevideo.com` на
  кэш-сервере провайдера: DPI перед ними бывает другим. Адрес считается рабочим,
  если ответ дошёл до конца или пришло больше 64 КБ: так ловится и «заморозка»
  соединения после 16 КБ. Каждый адрес открывается двумя видами ClientHello: большим
  TLS 1.3, как у современных браузеров, и коротким TLS 1.2, как у Windows и старых
  устройств. Если адреса не открываются, а интернет есть, FlowCloud перебирает
  встроенные стратегии и запоминает первую, которая открывает все адреса. Если такой
  нет, выбирается открывающая больше, чем текущая. Хост, который не открыла ни одна
  стратегия, на час исключается из проверок.
- Стратегию можно задать и вручную или указать свои аргументы `nfqws2`.
- Проверить вручную: `flowcloudd probe -zapret https://www.youtube.com/` и
  `flowcloudd probe -direct …` для сравнения.

## Переход с podkop

Обе службы перенаправляют DNS роутера и метят трафик. Одновременно включайте только
одну:
1. Остановите podkop: `/etc/init.d/podkop stop && /etc/init.d/podkop disable`.
2. В FlowCloud включите «Перенаправить DNS роутера» и сам FlowCloud.

При остановке FlowCloud возвращает dnsmasq прежние настройки DNS.

## Команды

```sh
flowcloudd status           # туннели, секции, DNS
flowcloudd status -json     # то же для LuCI и скриптов
flowcloudd update-lists     # обновить списки сейчас
flowcloudd diag URL         # пинг и загрузка напрямую, через каждый туннель и zapret2
flowcloudd warp-switch warp # сменить сервер WARP-туннеля warp сейчас
/etc/init.d/flowcloud restart
logread -e flowcloud        # журнал
```

## Сборка

```sh
GO=/path/to/go scripts/build.sh          # версия из файла VERSION
```

Пакеты появятся в `dist/`: `flowcloud_<версия>_<архитектура>.ipk` для aarch64, arm,
mips, mipsel и x86_64 и `luci-app-flowcloud_<версия>_all.ipk`. SDK OpenWrt не нужен:
пакеты собирает `tools/ipkbuild`.

## Ограничения

- Маршрутизация только IPv4.
- OpenWrt 25.x с пакетным менеджером apk пока не поддерживается.
- WARP-туннели требуют `kmod-amneziawg`; встроенного режима без модуля ядра пока нет.
- Трафик устройств, которые обходят DNS роутера (свой DoH в браузере), отслеживается
  только по подсетям.
